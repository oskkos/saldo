## Context

The `AbsenceReason` TypeScript enum (`src/types/index.ts`) and the Prisma
`Absence` enum (`prisma/schema.prisma`) both define the reason set
`holiday`, `flex_hours`, `sick_leave`, `other`. The saldo service tests
(`src/services/__tests__/index.test.tsx`) instead use `vacation` and
`unpaid_leave`, casting fixtures through `as unknown as Worklog[]` so they never
hit the type system or the database. The tests pass but encode a reason set that
does not exist in the running system. The baseline `absence` and `saldo` specs
recorded this as an open question.

## Goals / Non-Goals

**Goals:**
- Establish `holiday` as the canonical reason for annual/vacation leave.
- Make the tests reflect the real reason set so they document actual behavior.
- Close the reason-drift open question in the specs.

**Non-Goals:**
- Renaming the enum value (no `holiday` → `vacation` rename, no migration).
- Adding new reasons such as `unpaid_leave`.
- Any change to production code, UI, types, schema, or database.

## Decisions

**Decision: Keep `holiday`, fix the tests — do not rename to `vacation`.**

`holiday` is idiomatic for annual/vacation leave in European English, which fits
the app's audience, and it is already the value stored in the database and the
TypeScript enum. The tests are the only place the non-canonical names appear, so
correcting them is the smallest, lowest-risk resolution.

- *Alternative considered: rename `holiday` → `vacation`.* This would match the
  stale tests' wording and remove the surface-level clash with the app's
  public-holiday handling, but it requires a hand-written Postgres
  `ALTER TYPE "Absence" RENAME VALUE` migration (Prisma's autogenerated migration
  would do a destructive drop/add for an enum-value rename), plus changes across
  the enum, types, and a UI switch. That is disproportionate cost for a naming
  preference, and `holiday` is already a reasonable name. Rejected.

**Decision: Document the `holiday` semantics in the spec.**

To prevent the name from reading as "public holiday," the `absence` spec's
reason-set requirement is clarified to state that `holiday` means
annual/vacation leave and is distinct from auto-handled public holidays.

## Risks / Trade-offs

- [The name `holiday` still overlaps lexically with the app's public-holiday
  handling] → Mitigated by the spec clarification and (optionally, later) a code
  comment near the enum. Not addressed in code by this change.
- [Future contributors might re-introduce `vacation`/`unpaid_leave` in tests] →
  Mitigated because the corrected tests now use the typed enum values, and the
  spec records the canonical set.
